## О проекте

В диссертационном исследовании анализируется влияние некогнитивных навыков
(модель «Большой пятёрки») на занятость, заработную плату и удовлетворённость
работой молодежи в России. Эмпирическая часть основана на данных Российского
мониторинга экономического положения и здоровья населения (РМЭЗ).

Проект реализован как **полностью воспроизводимое исследование**:
все таблицы, графики и коэффициенты регрессионных моделей формируются
автоматически из первичных данных с помощью кода на языке R, объединённого
с текстом диссертации в среде Quarto.

## Воспроизведение результатов

### 1. Системные требования

* **R** ≥ 4.3
* **Quarto** ≥ 1.5
* **Python 3** (нужен только для пост-рендера DOCX)
* **TeX Live / MacTeX / TinyTeX** — для сборки PDF

### 2. Установка R-пакетов

Из корня репозитория:

```r
renv::restore()
```

`renv` установит все пакеты, зафиксированные в `renv.lock`, в локальную
библиотеку проекта.

### 3. Сборка книги

```bash
quarto render 04_thesis
```

Готовая книга появится в каталоге `04_thesis/_book/` в трёх форматах:
HTML, PDF и DOCX.

#### Кэширование и скорость сборки

Сборка использует два механизма кэширования, чтобы повторные рендеры
оставались быстрыми (~25 секунд против ~2 минут «холодного» прогона):

* **`04_thesis/_freeze/`** — кэш Quarto на уровне чанков.
  Чанк перевыполняется только при изменении исходника главы.
  Каталог фиксируется в git, поэтому кэш переносится между машинами.
* **`03_output/jobsatisf_outputs/jobsatisf_models.rds`** — кэш
  «тяжёлых» mixed-effects моделей главы 6. Модели подгоняются один раз
  и сохраняются на диск; при следующем запуске скрипт
  `02_codes/06_ncs_job_satisf/03_regressions_jobsatisf.R` загружает их
  вместо повторной подгонки.

Чтобы принудительно пересобрать тяжёлые модели:

```r
options(thesis.refit = TRUE)
# или просто удалить файл кэша:
file.remove("03_output/jobsatisf_outputs/jobsatisf_models.rds")
```

Чтобы сбросить кэш Quarto:

```bash
rm -rf 04_thesis/_freeze
```

### 4. Запуск отдельных скриптов

`project_config.R` определяет переменные путей (`processedData`,
`codesEmplNcs`, `outputsReturnsNcs` и т. д.). Эти переменные задаются
автоматически при запуске R в каталоге проекта (через `.Rprofile`),
поэтому скрипты в `02_codes/` запускаются без правок.

## Как код связан с текстом

Каждая глава в `04_thesis/` подключает соответствующие скрипты
из `02_codes/` через `source()`. Скрипты считывают подготовленные
данные из `01_data/processed/` и сохранённые объекты моделей из
`03_output/`. Это разделение позволяет:

* пересобрать тяжёлые модели отдельно, сохранив их как `.rds`;
* быстро ре-рендерить книгу без повторного обучения моделей;
* поддерживать прозрачное соответствие между текстом и кодом.
